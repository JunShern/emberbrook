## 2. Every number that is not a plain match

### 2a. slice_test drifted 830 -> 848, zero failures
Not a regression: 18 assertions were added since the brief's number was taken. `--town
emberbrook` returns the same 848, so the flag does not partition this gate.

### 2b. trigger_probe (live) was 67/13 and non-deterministic — a HARNESS defect, now fixed
Fixed in `5462b78`; it is green at **80 / 0**, twice in a row, and carries one assertion
MORE than the recorded baseline. The diagnosis, because two plausible causes were wrong:

The split was town-shaped — `emb-cine` 1/22 seam markers and 0/4 doors, `del-cine` a clean
40/40 and 6/6. Falsified first: **the fov-20 closeness round is not the cause**, because the
four closeness-limited shots (`orchard`, `square`, `pondlane`, `therise`) kept byte-identical
frames and lost their markers too. Falsified second: **not a runtime regression**, because
`markersTick` and `public/world/scenegraph.json` are both unchanged across the window.

The cause is that `markersTick` paints nothing while `UILOCK.active()` (play3d.html:1482).
Chapter One lives in Emberbrook, so story beats fired as the probe jumped between shots and
held the modal lock over the very thing being counted. Chapter Two needs Ch1 flags the probe
never sets — which is why Dellhollow measured clean, and why the count wandered run to run.
`de1df1c` had already added `?nostory=1` for exactly this case; the probe simply never took
the hatch, so it was measuring the story.

Its second failure was newer than the baseline and was **correct behaviour**: conditional
edges (`cb29471`) made the Old Gate a third `ow-valley` edge, SEALED until
`story.ch1.gate-open`, and `markersTick` refuses to draw onto a shut gate on purpose. The
probe asserted a marker on every non-auto edge, i.e. against the runtime's own law. It now
asserts both directions, so the seal is covered rather than tolerated.

## 3. THE CAVEAT THAT MATTERS: this baseline was taken on a MOVING tree

The cleanup brief stated the tree was committed clean at `c59006b`. **It was not.** Within
the ~25 minutes these gates were measured, other lanes landed six commits on this branch —
`5f75335`, `316fea6`, `ac8b2f2`, `6fb58da`, `11e21fb`, `c103e13` — and held uncommitted
edits in four tracked files, including **`public/play3d.html`** and a
`tools/blends/dellhollow-master.blend` whose mtime moved mid-measurement.

So each row above is honest about the gate, but the rows were not all taken against the same
commit. Anything that depends on a frozen tree — in particular the `play3d.html` -> `play.html`
rename, which renames a file another lane was editing at the time — must re-confirm its own
baseline at the moment the tree is actually quiet.
